# ING-003 入库失败恢复

ING-001 和 ING-002 拦截缺少可用正文的 PDF。原先的失败记录会提示页码并提供整份 PDF。馆员需将修正版作为独立文献重新上传，两份文件在系统内缺少关联。

## 馆员操作

1. 在 **上传与管理 → 文献管理 → 入库失败恢复** 选择等待恢复的文献。打开原件并按 PDF 页码核对问题页。没有页码的历史记录可直接打开原件。
2. 对原件做 OCR，或准备同一文献的可提取文字的 PDF。选择修正版，核对题名、作者、所属学科和副本对应的版本年份，然后点击 **提交修正版并重新验证**。
3. 修正版通过正文检查并完成索引后，恢复记录显示 **已恢复**，馆藏可搜索修正版。打开 **修正版记录** 可以查看各次提交的文件和处理结果。索引失败时，可在服务恢复后再次提交同一份修正版以继续处理。

原件、修正版和各自的文件哈希分别保存。失败尝试的文件仍可查验。恢复流程使用项目现有的正文检查和索引发布逻辑，OCR 由馆员在提交前完成。

## 实现与验证

- 从 main 开独立分支 `feat/failed-ingestion-recovery`，沿用 ING-001、ING-002 和批量入库的现有基础。
- SQLite 版本 3 增加正文诊断和原件与修正版的关联。读取旧记录时，从历史诊断中提取已有页码。
- `GET /document-recoveries` 列出处理记录。向 `POST /documents/{doc_id}/recovery/jobs` 提交 PDF，并通过现有文献任务接口查看进度。
- 验收检查正文阻断、可定位的 PDF 页码、两份原始字节、修正版检索、重复提交、索引中断重试、旧库迁移和中英文操作。见 [ING-003 验证记录](../validation/ING-003/README.md)。
