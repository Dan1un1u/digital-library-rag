# MQ-003 原因分析与修复候选

## 原因与复现

原增强任务 `c8bedaf42d164c47a262a0ece09a8014` 返回 FQ-ViT 的 year=2023，字段证据仅为 PDF 第1页的 `17 Feb 2023`，见 [原增强任务证据](enhanced-scope-assessment.json)。该日期来自所供 arXiv v4 的修订日期；正式出版年 2022 已由外部官方书目及用户抽查另行确认。

问题链条：

1. 原提示词要求出版/发表年份，排除了参考文献和 PDF 创建日期，但没有明确排除 arXiv 页边版本日期、修订、投稿及接收日期。
2. year 候选只有 value/pdf_page/excerpt，没有日期类型。模型将清晰可见的修订日期映射到出版年。
3. `merge_candidates` 原校验仅检查整数、年份范围以及摘录含有该数字；没有验证出版语境，也没有把年份摘录与实际页面文字核对。`2023 + 17 Feb 2023` 因而可通过。
4. 原合并逻辑还可能在拒绝 API 年份后保留未经核验的初始年份。修复必须约束增强输出的最终 year，而非只筛掉一个模型值。

这是增强识别输出的语义约束与证据校验问题；本次不修改本机抽取算法，也不扩大 MQ-001/MQ-002 的课题范围。

## 方案比较与选择

| 方案 | 能解决的问题 | 局限 |
| --- | --- | --- |
| 只改提示词 | 减少模型把修订日期当作出版年 | 模型输出具有不确定性，原弱校验仍会接受相同错误 |
| 提示词 + 日期类型 + 出版证据校验 | 在增强边界拒绝日期语义错误，并保留可追溯的审核状态 | 缺乏出版证据时会留空，需要复核 |
| 查询权威书目补全年份 | 可进一步查得 FQ-ViT 的正式年份 2022 | 涉及外部服务、标识匹配与冲突处理，属于 MQ-004 扩展 |

本次采用第二种方案，第三种留在 MQ-004。没有从 arXiv 编号、文件名或模型记忆推算正确出版年。

## 实现

- 提示词明确禁止用 arXiv/预印本版本、修订、投稿、接收、PDF 创建日期代填出版年；非空 year 需附 date_type 和含出版语境的原文短句。
- 新增 `metadata_year.py`，作为增强结果的校验环节。日期类型标签本身不视作证据；只有合理年份、对应出版/版权语境和页面证据均满足时才接受。
- 可提取文字时核对真实页面正文，排除仅出现在参考文献区的摘录；不能用页面没有的 Published 或 © 标记补造依据。
- 保留完整页文字用于服务器校验，向模型发送的文本仍限制为每页 6000 字符并附页面图像，防止真实出版页脚因文本截断而被误拒绝。
- 无出版证据时 year 留空，输出 `year_review` 和“出版年份待核对”提示；其他有效字段继续保留。已有初始 year 只有经同等出版证据校验后才保留。
- 既有 metadata.year 仍为整数或 null；新增审核信息位于预览结果外层，不改数据库结构，不修改现有馆藏。人工更正后仍可正常入库。

图像页没有可提取文字时，符合出版语境的摘录仍来自模型读图，标注 `grounding=model_read_page_image`，不声称有独立 OCR 证实。仅有日期数字的图像摘录仍拒绝。人工审核要求保留。
