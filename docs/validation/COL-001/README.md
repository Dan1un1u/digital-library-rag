## 复现

使用 Python 3.11 或 3.12 创建独立虚拟环境，安装 `app[dev]`，然后在仓库根目录运行：

```powershell
.venv/Scripts/python.exe scripts/run_catalog_checks.py --scope new
.venv/Scripts/python.exe scripts/run_catalog_checks.py --scope all
```

首次使用 tiktoken 时会获取编码表；已有编码表可用 `--tokenizer-cache <本地缓存目录>` 复用。测试进程显式采用 mock、清空模型密钥，使用临时数据库和合成 PDF；不会向正式馆藏导入文献或调用真实 BGE/Luna。

本机验证环境在仓库内新建 `.venv`，以只读路径复用既有独立部署的第三方包，在新环境中安装 editable 当前仓库与 coverage 7.16.2。运行器会确认 `dlrag` 来自当前仓库，避免测到旧部署。UTF-8 在子进程启动前明确设置，避免 Windows 默认编码影响 SQL 等文件读取。

运行器在忽略的 `reports/COL-001/` 中保存完整日志、JUnit、分支覆盖率 JSON 和摘要，拒绝复用输出目录。摘要记录被测提交、执行前后工作区状态、环境版本、新增/复用用例数、语句与分支覆盖率、未覆盖行与分支，以及原始产物 SHA256。正式归档应基于干净的已提交源码；开发中 dirty=true 的运行不冒充提交验证。

覆盖率对父测试进程计量；少数既有 CLI 子进程未启用覆盖追踪，不能将相应未覆盖行直接解释为未执行。全套测试与新增用例的覆盖范围分别保存，不能将全套覆盖率全部归因于新增用例。语句覆盖与分支覆盖分开报告，不以一个混合百分比代替两者，也不追求虚报 100%。

## 已发现并修复的问题

- 新增批次工具的首轮开发测试发现：文件哈希与事件哈希共用 `sha256`，导致序列化后不能重算事件摘要。现将事件摘要命名为 `event_sha256`，在中断和成功回执上逐条验证链条。
- 初次直接运行测试未设置 UTF-8，Windows 默认编码导致原有 SQL 文件读取失败，表现为 library 未装配。运行器明确设置 UTF-8；这属于环境前置条件，不计作已修复的业务功能缺陷。
