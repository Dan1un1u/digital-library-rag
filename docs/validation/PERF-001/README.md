# PERF-001 批量入库与增量向量索引

馆员可在「上传与管理 → 批量入库」选择多份 PDF，逐篇核对标题、作者、版本年份和学科，再提交整批。正常批量一次发布索引。旧向量的复用条件包括片段 ID、实际编码文本、嵌入后端标识、分块配置和归一化设置。词法索引及版本清单随整批更新。

## 同库对照

在独立开发目录，从正式库的一致副本移出 COL-006 的六份测试文献，建立同一个 169 篇、16,135 片段的起始索引。两组使用其副本、相同六份 PDF 与已确认元数据、同一台机器及同一 BGE-M3 FP16 模型修订。基线为 `66924ad`，候选为 `a9837c7`。

计时从已核对的文件进入后端入库开始，到索引发布和结果返回结束。基线连续走 6 次 `Services.ingest`，候选走 1 次 `Services.ingest_batch`。本次单轮配对测试涵盖解析、向量计算、存储和索引发布，逐篇人工核对及增强识别位于计时之前。

| 指标 | 逐篇全量重建 | 批量发布并复用向量 |
| --- | ---: | ---: |
| 后端入库耗时 | 903.45 秒 | 13.26 秒 |
| 实际送入嵌入后端的片段数 | 98,823 | 564 |
| 索引发布次数 | 6 | 1 |
| 最终馆藏 | 175 篇、16,699 片段 | 175 篇、16,699 片段 |
| 6 篇新增和 1 篇已有文献在三种检索中的前 20 命中 | 21/21 | 21/21 |

两组最终正文语料与词法索引的 SHA-256 分别一致。向量输入量下降 99.43%，实际节省时间以本次同机同库复测为准。证据见 [baseline.json](baseline.json) 和 [candidate.json](candidate.json)。

## 回归

- 4 项 API 和索引用例先在原代码复现，候选再加入 1 项英文界面的双文件录入测试，5 项均通过。
- 覆盖全批一次发布、重复上传、混有坏 PDF、索引构建失败后旧库可查、重试和变更配置重新编码。
- 既有嵌入失败用例改为提交确实需要编码的新内容，保留对旧索引和内存快照的断言。
- 完整回归 **637 项通过**。复测使用 `python -m pytest -q app/tests/integration/test_batch_ingestion.py app/tests/retrieval/test_retriever.py`。
