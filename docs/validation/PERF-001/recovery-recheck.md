# PERF-001 发布失败与重启复验

对照 PR21 的 `ddf70b6` 和修复提交 `44d118c`。两组通过批量入库 API 提交同样两份测试 PDF，在独立 SQLite 的第二条就绪状态写入处触发真实语句失败，并读取任务结果、馆藏列表、磁盘索引指针和检索响应。

| 核验项 | 修复前 | 修复后 |
| --- | --- | --- |
| 两篇文献的状态 | 一篇就绪，一篇待索引 | 两篇均待索引 |
| 任务报告与检索服务的索引版本 | 任务报旧版本，检索用新版本 | 两者均为上一次已提交的版本 |
| 磁盘索引指针 | 已切到新版本 | 与入库前的指针字节一致 |
| 待索引文献可见性 | 文献列表缺席，检索可命中 | 文献列表及检索均等待成功发布 |

一批文献的就绪状态在同一个 SQLite 事务提交。索引发布前写入恢复记录。重启按 SQLite 的提交结果恢复旧索引或保留已提交的新索引。移除故障后可以重试已解析文献。

改前已有旧索引和空库的两条语句失败用例均失败。修复后批量入库目标用例 **13 项通过**，覆盖 SQLite 语句失败和事务提交失败、空库和已有库、重试、默认和自定义启动，以及中断时数据库已提交与尚未提交。全量回归 **645 项通过**。

## 同馆藏性能复测

在原 169 篇基线的独立副本上添加相同 6 份 PDF。使用同一 BGE-M3 FP16 模型修订，后端单轮耗时 **14.23 秒**，编码 **564 个片段**，发布索引 **1 次**。最终 175 篇、16,699 个片段，与原对照相同的正文语料和词法索引哈希，三种检索抽查 **21/21 命中**。计时从元数据已确认后的后端入库开始，到返回发布结果结束。

见 [故障响应对照和性能复测](recovery-recheck.json)。
