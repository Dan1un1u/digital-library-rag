# MQ-006：关键词与LLM辅助学科分类

本轮在PR9补齐自动分类。上传PDF后，程序先根据题名和主题词匹配学科；没有唯一匹配且开启“增强识别”时，由LLM结合前两页判断。结果自动预填“所属学科”，同时显示来源页码、原文摘录和简短理由，用户可以修改。

## 使用方式与实现

1. 上传PDF，保持“增强识别”开启。后台先执行共用的学科规则。
2. 没有明确标签且关键词未得到唯一结果时，现有页面识别请求中的 `classify_discipline=true` 会让LLM同时返回学科；标题、作者等信息共用这次请求，无新增独立模型调用。
3. 结果只接受自然科学、社会科学、哲学与人文科学之一，核对原文依据后写入预览的 `metadata.topics`，在页面下拉框自动选中。关键词已匹配时采用规则结果。
4. 核对字段后正常导入。原有入库检查继续检查最终标签；接口或批次导入应先取得识别预览、完成字段确认，再提交元数据。

关闭“增强识别”、管理员禁用API、缺少密钥或处于mock环境时，不调用LLM。关键词仍可分类；没有结果、调用失败或模型未给出可用分类时，页面保留手动选择。已有的明确学科优先，用户在导入前修改的选择不会被模型覆盖。浏览旧馆藏不会触发模型调用，也不会自动改写历史记录。

实现位置：`shared.disciplines`提供三类标签及共用规则，`ingestion.discipline`核对并合并分类，`ingestion.metadata_api`复用硅基流动页面识别请求，上传页面展示分类来源并预填表单。项目接口及模型服务仍沿用原配置；个人测试接线位于仓库外。

## 测试中发现并修复的格式问题

第一轮真实预览里，LLM已经正确判断Ascend属于自然科学，但它把PDF中的 `devel-` 换行 `oped` 还原为 `developed`，原文摘录匹配因此失败。增加了Unicode与换行断词兼容，并保存捕获候选、复现用例和前后执行记录。

第二轮里，CSB-RNN的模型摘录使用省略号连接两段文字，无法作为一个连续原文片段核对。现在提示模型只摘录一个短句；若仍出现省略号，只保留能在PDF核对的连续片段，未核实的其余片段不展示。新用例同时验证了这一行为。上述两轮失败均发生在预览阶段，当时dev库仍为空。
