# v1.3 回答覆盖与相关性修复

日期：2026-10-18。修复“问如何阅读长文本，回答却只是把长文本作为输入”的问题，保留 v1.2 的角标跳转与原文高亮。

## 问题定位

之前同题记录中，8 个片段已经送入模型，包含 Transformer、计算代价和上下文窗口等正文，模型仍只生成一句泛泛的结论。原本的“相关性重排”主要是本地正文 BM25 与检索排名混合，并非神经语义重排；同时邻居奖励和文献多样性偏好可能让一般背景挤占直接解释机制的正文。

原十篇馆藏也偏重检索与长上下文实验，缺少输入表示和注意力机制的基础正文。再加上 v1.2 要求模型同时组织正文、复制长片段编号并选择句子编号，定位格式错误会导致整次回答修复或失败。这些问题不能靠增加引用数量解决。

## 实现变化

### 机制检索与语义重排

- 查询规划新增最多 4 项 `answer_requirements`，明确需要回应的问题要点；如何类问题优先考虑具体处理过程、信息表示或利用方式、限制与应对，不擅自扩展背景案例。
- 新增最多一条 `mechanism_query`，作为机制正文的补充检索，仍使用同样的年份与主题过滤条件。中文问题通常为中文、英文和机制查询最多三路，每路最多20个命中，按已有RRF融合。关闭双语时不执行中文问题的英文机制分支。
- 接入 `Qwen/Qwen3-Reranker-4B`。针对原问题与机制查询分别评分，避免把所有要点拼成一条宽泛查询，漏掉只回答某个关键步骤的正文。候选上限60个，每次请求超时20秒，无隐藏重试。适配参照[硅基流动官方重排接口](https://docs.siliconflow.cn/docs/api/rerank-post)。
- 证据选择增加尚未覆盖方面的增益偏好，保留参考文献降权和相邻正文；降低语义排序场景下的邻居奖励与文献多样性惩罚，让直接相关正文有机会优先进入8块上下文。评分与增益属于选择启发式，不是经过校准的正确率。
- 参考文献判断补充“两段作者—年份—题名条目”模式，避免两条参考文献因不足原阈值而被当作机制正文。普通正文中的括号引用和“参考条目加正文”的混合块不直接等同于纯参考文献。

### 回答与覆盖检查

本机最终配置为 `Qwen/Qwen3-32B`，显式 `LLM_ENABLE_THINKING=false`；输入保守预算上界24000、模型上下文上限32768、输出上限1800、请求超时90秒，仍最多8块证据。配置位于 `.env`，可复制示例位于 `.env.example`；Python类的旧默认值为兼容保留。

回答要求先解释证据中的实际步骤和机制，再说明相关限制或改进；不能用实验现象代替机制，不能把特定架构推广为所有模型，也不能把“趋于饱和”改写成“下降”。所有实质事实仍必须引用本次选中的证据。

生产模式使用简化生成结构：模型只写正文、引用的短片段编号和实际限制，不再负责生成sections、coverage或句子编号。后台恢复真实引用，按可读长度组织自然段，并使用语义重排将问题要点关联到正文。弱关联或没有直接关联的要点显示为回答范围。这样避免模型因整理要点或编号失败而误判为证据不足。兼容的full模式仍支持原有结构校验及最多一次修复。

`coverage`为服务端关联结果，不是独立的事实正确性审核；关联强弱的阈值是启发式，未经正式校准。它帮助定位遗漏范围，不能证明所有关键细节都被覆盖，也不能作为正式覆盖率。

### 独立句子定位

生产配置不再让生成模型复制句子编号。生成时使用本次请求内的短片段编号，后台恢复为真实 chunk_id，再对每条结论和其引用片段中的句子进行语义重排，选取最相关支持句。真实偏移和高亮文字由原文确定，公共响应再次校验精确子串。每条引用通常保留最相关的一句，第二句仅在评分接近且较高时补充。

这样通常仍只有两次生成调用：规划一次、回答一次。定位使用重排服务，额外请求数取决于结论数量；要点关联最多另加4次重排请求。在进度中分别显示“定位支持回答的原文句子”“核对回答与问题要点的关联”，并分别记录用时。没有把引用数当作覆盖率指标，也没有固定凑字数。

语义排序失败时明确提示使用本地排序；句子定位失败时保留可核对的片段引用，明确提示缺少句子高亮，避免引用定位故障吞掉整个回答。不编造句子或偏移。

### 界面

回答上方分别显示检索去重数、重排候选数、选入上下文数和最终引用数。提供“问题要点与回答范围”展开项，保留自然段、引用角标、来源页和 PDF 高亮。进度显示实际进入的阶段与用时。

## 验证与边界

完整自动测试及最终真实响应、引用检查、耗时见 `evaluation/qa/v1.3/delivery_check.json`。新增测试覆盖语义响应结构、排序与参考文献惩罚、机制查询过滤、覆盖缺口、短编号还原和冲突、句子定位、服务降级及普通正文与参考文献的区分。

最终完整测试为296 passed、2条既有提示。浏览器原问题实测32.0秒完成：53个检索去重片段、58个重排候选、8个上下文片段、5个最终引用片段；生成6条说明，组织为2个自然段，未触发格式修复。问题要点关联及句子定位均成功。界面截图为 `evaluation/qa/v1.3/ui_final_answer.png`。这些是单次开发观察，不代表稳定延迟或正式质量成绩。

最终浏览器原问题记录为 `browser_final_answer.json`，无关问题的拒答记录为 `delivered_unrelated.json`。`final_mechanism.json`和`complete_answer.json`为简化生成前的开发成功样本；其他live、final_1、accepted等文件含探索性失败或不完整输出，不作为交付质量依据。比较过程中DeepSeek-V3.2完整请求出现超时，未保留为最终运行配置。

真实开发检查用于确认问题机制得到更直接的解释、引用可以还原和高亮，并不代表整体语义评测通过。60道候选题仍未经人工复核；不得据此宣称正式准确率或普遍覆盖率已经达标。完整性和相关性仍需在更多类型问题上人工评估。

重排会将最多60个候选文本发送给现有硅基流动服务；句子定位会发送生成结论及所引用片段中的候选句，生成服务收到选中的上下文。元数据预览继续在本机完成。密钥只通过运行进程注入，未写入修改文档或新代码。
