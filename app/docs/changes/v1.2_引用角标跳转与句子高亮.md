# v1.2 引用角标跳转与句子高亮

日期：2026-10-18。承接 v1.1 的连贯回答与实际阶段进度。

## 使用方式

回答中的 `[1]`、`[2]` 已改为可点击的上标链接。点击后在新标签打开对应来源页，自动定位到“引用原文”，用黄色高亮直接支持当前结论的具体句子。来源页还显示文献标题、PDF 文件页号、原文件入口及带高亮的 PDF 原页预览。

同一个文献片段支持多条结论时，角标编号保持一致，但各角标的链接可携带不同句子位置，分别高亮各自支持的句子。回答下方的“查看原文”按钮继续保留；展开片段时汇总高亮该片段在本次回答中被引用的句子，并提供来源页入口。

升级前的历史回答没有句子定位信息，需要重新提问以生成精确高亮。旧回答仍可查看全文，界面会明确提示缺少定位；不使用相似度猜测句子。

## 生成与校验

服务为每个候选片段中的句子添加局部编号 `[s1]`、`[s2]`，只在发送模型的提示中使用。原始索引文字、证据 quote 与 PDF 均不因此改变。句子切分是中英文标点启发式，保留原字符位置；遇到缩写、版式和原切片边界时，句子可能较长或不完整，不能视为语言学上的完美分句。

模型在原有最终回答调用中，为每条结论返回 `evidence_sentences`，指定每个所引用 chunk_id 下直接支持它的句子编号。真实服务装配启用 `sentence_citations_required=True`，要求每条结论的所有引用均提供句子定位。非法编号、遗漏引用或缺少定位会触发现有的最多一次修复；未修复成功时返回校验错误，不生成虚假高亮。独立引擎调用默认保留旧输出兼容，可显式启用此要求。

公共 Claim 新增可选 `citations`，包含 evidence_id 和 highlights；每条高亮由服务根据原文生成 start、end、text，采用 Python 字符偏移和左闭右开区间。公共响应再次验证高亮文本等于对应 evidence.quote 的精确子串。模型不直接生成偏移、原文、页码或链接。

句子编号仅增添少量标记，没有重复发送整段原文，也没有额外增加定位模型调用。提示及编号纳入现有上下文预算；检索索引与文献无需重建。结构校验不能替代人工判断结论是否真正被选中句子支持。

## 来源页与 PDF 高亮

新增 `GET /sources/{chunk_id}?index_version=...&span=start:end&span=...#source-text`。参数只包含索引版本与位置，不在链接中传输原文或密钥。入口按受控片段 ID 查找文献，核对索引版本、片段归属及完整句子边界；非法位置返回 422，片段不存在返回 404，索引更新返回 503 并提示重新提问。

提取原文使用经过转义的 HTML 与 mark 高亮，支持重叠句子位置合并；模型和原文中的 HTML 均作为文字显示。页面设置无脚本的内容安全策略、禁止缓存，并使用受控的原文件链接。

PDF 原页通过 PyMuPDF 文字层查找对应句子，在内存中添加高亮后渲染 PNG。渲染最长边限制为 1800 像素以内，不写回 PDF、不产生永久批注。如果句子因文字层、跨栏或抽取排版等原因无法定位，会报告 PDF 匹配成功数；提取原文的精确高亮仍可核对。PDF 同页重复出现完全相同的文字时，预览可能高亮所有准确匹配位置。原文件链接打开的是未经改写的 PDF。
