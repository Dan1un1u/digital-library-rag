# PDF 自动识别与切分策略

2026-10-18 新增本地元数据预览。管理与实验页选择 PDF 后自动识别并预填，核对或修改后点击“导入并建立索引”。作者每行一位，保留姓、名之间的逗号。“重新识别文献信息”会重新预填当前文件；普通页面刷新保留已编辑内容，换文件时清空上个文件的字段并重新识别。

## 识别范围和来源

优先读取 PDF 自带 title/author；缺失时按首页字号、位置及标题后的姓名行提出候选。处理多行作者、同排分栏作者和常见姓名脚注，排除邮箱和明显机构行。只有首页明确的出版日期/版权年份才提出年份候选，不把 PDF 的创建或修改时间当出版年份。从首页文献标识提取 arXiv/DOI 来源，避免误取后页参考文献；从前两页中英文字分布提出语言候选。主题与使用权限说明仍需人工填写。

全部在本机用 PyMuPDF 和规则完成，不调用模型、联网或上传原文到外部平台。预览不新增文献、文本块或索引，仅最终确认导入后写入馆藏。识别结果带来源和提醒；复杂排版、扫描件、错误内嵌元数据、姓名重音或分栏顺序可能导致识别错误，不能当作已核验书目信息。扫描件未启用 OCR，无法识别时字段留空，仍可手动填写。

新增可选接口 `POST /documents/metadata`：multipart 参数为 file，返回 metadata、field_sources、warnings、requires_confirmation=true、page_count。类型/大小限制与正式导入相同（默认25MB），非法或加密PDF返回422，临时文件请求后清理。原 `POST /documents` 接口和数据契约不变，以用户最终提交的字段入库，不擅自覆盖手工修改或已有去重记录。

## 当前实际切分

本机配置明确采用 `count_mode=character`，最大1200字符，强制切断时重叠最多150字符。步骤为：

1. 按 PDF 文件页序提取文字和布局块，不跨页拼接。
2. 清除空字符、整理空白与可见断行，并保守删除多页重复页眉/页脚；双栏正文仍需核查阅读顺序。
3. 在当前长度预算内优先选择最后一个段落边界，其次选择句末边界；预算内无合适边界才按长度强制切断。
4. 仅在强制切断长段/长句时向后保留最多150字符重叠；正常段末、句末切分不额外重叠。
5. 每块保存PDF文件页号、原规范页面文本的半开偏移[start,end)及稳定编号，保证块文本等于该页面切片，引用可回到原页。

所以1200是上限，并非每块固定长度；150也不是所有相邻片段都有的固定重叠。字符不是token，当前块的token_count为null，char_count记录实际字符数。上传时不会先用LLM改写正文，也未做语义模型切块。

程序另支持 `count_mode=token`：使用真实 `tiktoken:<encoding>`，默认max_tokens=400、overlap_tokens=50，仍采用相同的按页和边界策略；需要明确配置tokenizer及版本，失败不静默换计数口径。对已有同一PDF改变切块配置应离线重建库和索引，再核验标注，不能直接用新配置查询旧块。

## 验证记录

新测试覆盖内嵌元数据、首页标题/多行作者、机构/邮箱排除、创建时间不冒充出版年、无文本/坏/加密PDF、预览不入库、用户修改优先、换文件重置及重复渲染保留编辑。全量结果见 evaluation/reports/metadata_upload_tests_20261018.xml。

现有十篇真实PDF的预览记录在 evaluation/ingestion/metadata_preview_20261018.json。能提出候选并不保证元数据完整准确，作者数量相同也不代表每个姓名或排序均正确；例如 PDF 的姓名重音字符仍可能需要手工更正。此轮不调用外部API、不更改既有馆藏或重建索引。
